Exemples concrets de combinaisons (niveau × interface × angle × type)
Cette page est le compagnon pratique des pages de fondation sur les niveaux dʼintégration et les catégories de validation. Son objectif est de montrer, par lʼexemple, comment les axes se combinent concrètement.
Important. Cette page nʼa pas pour but dʼêtre exhaustive dès le départ. Elle sert à rendre
les concepts visibles, à éviter les ambiguïtés classiques et à aider les équipes à nommer précisément ce quʼelles valident.
Note terminologique : cette page contient des exemples pratiques de combinaisons
niveau × interface × angle × type. Les définitions de référence des termes utilisés sont maintenues dans le Lexique / Terminologies. Les exemples ci-dessous illustrent lʼusage opérationnel des termes, sans remplacer le lexique ni la page de fondation Les tests (niveau × interface × angle × type).

Comment utiliser ces exemples en équipe
1. Planification. Pour chaque spécification, préciser le niveau, lʼinterface, lʼangle et le type de validation attendu.
2. Revue de stratégie. Identifier les trous de couverture : trop de small applicatif, pas assez de medium machine, aucun large UI, etc.
3. Désaccord de vocabulaire. Remplacer les débats sur « unitaire », « intégration » ou « E2E » par une description précise du périmètre réel.
4. Architecture. Utiliser les combinaisons pour prévoir les contrats, mappings, mocks, stubs,
simulateurs et environnements nécessaires.
