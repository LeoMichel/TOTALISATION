Comment implémenter🎯 Objectif de la phase IMPLÉMENTERLa phase IMPLÉMENTER est le cœur du FORGE où les stories déjà prêtes, découpées etvalidées en PLANIFIER sont codées, intégrées, testées et documentées. La spécification devient du code fonctionnel, conforme et prouvé.Implémenter, ce n'est pas juste coder. C'est traduire fidèlement lesspécifications en code, en tests et en preuves de conformité — sansinterpréter, sans deviner, sans improviser.Principe fondamental : les spécifications atomiques issues de DÉFINIR sont la seule source de vérité. Le développeur code ce qui est spécifié. Le QA teste ce qui est spécifié. L'intégrateur valide ce qui est spécifié. Tout le monde travaille à partir du même artefact.Note terminologique. Cette page décrit la phase IMPLÉMENTER dans son contexte opérationnel. Pour les définitions de référence des termes utilisés ici — spécification IF… THEN…, spécification atomique, DoR, DoD, validation, vérification, test, niveaux dʼintégration, interfaces, angles dʼobservation, intégration, contrat dʼintégration, CI/CD, artefact, dette technique, qualimétrie, rôles et RACI — voir le Lexique / Terminologies et la page SPÉCIFICATION.Les descriptions locales précisent lʼusage de ces notions pendant IMPLÉMENTER. Lescontributions indiquées dans cette page sont propres à cette phase et ne remplacent pas la matrice RACI. Les anciens termes comme critère dʼacceptation, cas de test ou scénario convergent ici vers la spécification IF… THEN… et ne doivent pas recréer une couche séparée.🔀 Le passage de DÉFINIR / PLANIFIER à IMPLÉMENTERAvant de commencer, les prérequis suivants doivent être satisfaits :PrérequisVérificationFEATURES découpées en storiesChaque story est claire, cohérente et traçable à sa spécification atomique.Couverture des spécificationsOn sait exactement quelles spécifications atomiques sont couvertes par chaque story.Stories estimées finementEffort, complexité et capacité validés par l'équipe.Priorités validées par le POSelon la valeur, le risque et les dépendances.DoR satisfaitClarté, testabilité, dépendances gérées,estimation validée.Pré-requis techniques validésEnvironnements, outils, accès, données et configurations disponibles.Dépendances planifiéesAucune dépendance bloquante non résolue.Si le DoR n'est pas satisfait, la story ne rentre pas en implémentation. C'estune règle, pas une suggestion.🛠 Ce que « implémenter » veut dire concrètementImplémenter couvre quatre activités indissociables qui se font en parallèle, pas en séquence :1 SPÉCIFICATION ATOMIQUE 2↓3    ┌────┴────┐────────┐────────────┐ 4    ↓         ↓        ↓            ↓5 CODER    TESTER   INTÉGRER   DOCUMENTER 6↓         ↓        ↓            ↓7└────┬────┘────────┘────────────┘ 8         ↓9 STORY TERMINÉE (DoD satisfait)1. 💻 CODER — Traduire la spécification en codeLe code est une traduction directe de la spécification atomique, pas une interprétation.Le développeur implémente exactement ce qui est spécifié : ni plus, ni moins.Si la spécification est ambiguë ou incomplète, on ne devine pas : on retourne à DÉFINIR.Le code respecte les standards de développement, de sécurité et de conformité du Contrat qualité.Les revues de code sont effectuées et approuvées par les pairs.2. 🧪 TESTER — Prouver la conformité à tous les niveauxLes validations et tests sont dérivés directement des spécifications IF… THEN…, sans couche séparée de critères dʼacceptation.Les tests suivent lʼapproche RED4GREEN : écrire ou ajuster le test qui échoue dʼabord, puisimplémenter jusquʼà obtenir un résultat vert.Les tests couvrent les niveaux pertinents : Small, Medium et Large / E2E.Les approches whitebox, blackbox et graybox peuvent s'appliquer à tous les niveaux.La couverture unitaire minimale est de 60 % lorsque mesurable.Les spécifications critiques doivent avoir au moins une validation associée et un résultatdocumenté.L'automatisation est la règle ; le manuel est l'exception justifiée. Les tests automatisables doivent être intégrés au pipeline lorsque pertinent.NiveauCe qu'on testeCe qu'on prouveSmallLe plus petit comportementisolable.La logique interne fonctionnecorrectement.MediumL'intégration entre composants.Les contrats, échanges et dépendances fonctionnent ensemble.Large / E2ELe comportement complet du point de vue utilisateur ou système.Le flux de bout en bout produit le résultat attendu.3. 🔗 INTÉGRER — Assembler et valider les contratsLe code est intégré dans la branche principale ou la branche de release appropriée.Les vérifications CI/CD passent sans erreur.Les contrats d'intégration sont respectés et validés avec les systèmes partenaires.Les dépendances inter-équipes sont intégrées et testées.Les artefacts de build sont générés, versionnés et stockés dans les dépôts officiels.4. 📝 DOCUMENTER — Maintenir la traçabilité vivanteLa documentation technique est mise à jour : code, API, configuration, changelog.La documentation est liée aux spécifications, pas gérée comme un document séparé en silo.La traçabilité spécification → code → tests → résultats est maintenue.Les risques, anomalies critiques et dettes découverts pendant l'implémentation sontdocumentés et remontés au backlog ÉLICITER pour préserver la boucle de rétroaction.🔄 La boucle spécification → code → testLe code et les tests sont deux faces de la même spécification :1 SPÉCIFICATION ATOMIQUE 2↙              ↘3 CODE              TESTS 4↘              ↙5CONCORDANCE 100%Le code implémente le comportement décrit dans la spécification.Les tests vérifient que le code respecte la spécification.Si le test échoue, soit le code est incorrect, soit la spécification doit être clarifiée.Il n'y a jamais de code sans test, ni de test sans spécification.Si tu ne sais pas quoi tester, c'est que la spécification n'est pas assez claire. Situ ne sais pas quoi coder, c'est pareil.🤖 IA et automatisation pendant l'implémentationLes spécifications atomiques solides permettent d'utiliser l'IA comme levier pendantl'implémentation :LevierApplication concrèteGénération de code assistéeL'IA génère du code conforme à laspécification ; le développeur valide et ajuste.Génération de tests automatiséeL'IA dérive des validations automatisées à partir des spécifications IF… THEN… et des exemples.Auto-validationVérification automatique que le code respecte la spécification.Détection de régressionsL'IA identifie les impacts potentiels d'unchangement sur les tests existants.Revue de code assistéeL'IA détecte les incohérences entre le code et la spécification.Test de qualité : est-ce que l'IA peut générer le code ET les tests à partir de laspécification seule ?
